# 轨道仿真可信度诊断系统

**Orbit Simulation Trustworthiness Diagnosis** · AGH 智能体驱动

> 给出仿真配置，智能体自主完成多步诊断，输出**「能不能信、依据是什么、该怎么改」**。

---

## 这个项目解决什么问题

数值仿真有一个特性：**参数取错了，程序照常跑完，输出的数看起来也很正常。**

- 步长取太大 → 结果慢慢偏离，每一步都"看起来没错"
- 步长取太小 → 误差被浮点精度淹没，看似"很精确"
- 守恒量对得上但位置偏了 → 两个指标各说各话，单看任何一个都发现不了

**这些都不产生错误提示。** 工程上判断仿真可信度（V&V）传统依赖人工经验——设计算例、跑多组、画图判断，一轮大半天，而且换个人结论可能不同。

本项目把这条流程做成了**智能体可自主跑完的闭环**。

## 核心能力

### 五个工具（注册为 AGH 后端工具）

| 工具 | 回答什么问题 |
| --- | --- |
| `orbit_kernel_info` | 有哪些积分方法可用、各自几阶、精度极限在哪 |
| `orbit_propagate` | 算一次：位置误差（对解析解）+ 两个守恒量相对误差 |
| `orbit_order_test` | 实测收敛阶 vs 理论阶——**验证实现本身有没有写错** |
| `orbit_calibrate_step` | 由目标精度反推所需步长，并给出浮点上界 |
| `orbit_alarm_check` | 六条规则体检 + **误差预算**：能不能交付、瓶颈在哪、还能不能更好 |

> **关于维度**：内核以**轨道平面内的二维坐标**为状态量（`nq = 2`），场景参数为半长轴、偏心率、引力常数。
> 任何二体轨道都在一个平面内，三维解只差一次正交旋转，因此**位置误差、守恒量、收敛阶与规则判定都不受朝向影响**。
> 需要三维坐标时用 `orbital-elements.mjs` 的 `elementsToState()`——该转换已与 Orekit 官方测试对拍到 1.2e-15。

### 四件在检索中未见同类的事

1. **误差预算分解**——把总误差拆为截断 / 浮点 / 参考解三项，判定瓶颈，**并给出改进方向**
   （它是 `orbit_alarm_check` 的**运行时返回字段**，不只是事后整理的文档）
   - 实测：763 步/圈时浮点占比 **0.015%**（瓶颈=截断，缩步长有效）；6125 步/圈时升至 **52.99%**（瓶颈已转移到浮点，此时再缩步长收益递减，工具会建议改换方法）
2. **「守恒量达标但位置超差」做成自动致命级报警（R1）**——领域已知陷阱的形式化
3. **判断可审计**——用**确定性规则**核对智能体输出，不让模型自审
4. **判据写在代码里，模型不打分**——判定结果可复现、不随模型版本漂移

## 快速开始

### 不需要安装 AGH，就能跑验证

```bash
# 需要 Node.js ≥ 22（内核自包含，无第三方依赖）
cd agh-orbit-plugin

# ── 一条命令跑完全部验收（推荐先跑这个）
node verify-all.mjs          # 快速集 8 项，约 10 秒
node verify-all.mjs --full   # 含网格统计等慢项
# 若所在环境的子进程受限，用同目录的 verify-all.ps1 或 verify-all.cmd

# ── 也可逐项运行
node verify-kernel.mjs           # Python ↔ JavaScript 两套独立实现逐项对拍
node smoke-tools.mjs             # 五个后端工具的基本调用与返回结构
node test-error-budget.mjs       # 误差预算验收（27 项断言）
node test-confidence.mjs         # 统计置信区间验收（25 项断言，与 scipy 对拍）
node test-external-benchmark.mjs # 与 Orekit 官方测试、Curtis 教材例题对拍（8 项）
node transfer-test.mjs           # 可迁移性验证（二体 ↔ 简谐振子）
node loop-runner.mjs             # 四步闭环编排（5 个目标）
node diagnose.mjs                # 五种积分器的标定口径与收敛阶实测
node grid-eval.mjs               # 六场景 480 单元统计 + 置信区间
node integrator-guide.mjs        # 生成积分器选用参考表
```

退出码 `0` 即通过。全部留档写入 `agh-orbit-plugin/out/`。

> **提示**：`orbital-elements.mjs` 与 `confidence.mjs` 是被上面脚本引用的**模块**（要素⇄状态转换、Clopper-Pearson 置信区间），
> 不需要单独运行。

> **想看数值内核在做什么**：打开 `docs/判断链路可视化-一次完整诊断.html`，那是 AGH 会话的完整记录。

### 装进 AGH

1. 把 `extensions/agh-orbit-toolkit/` 复制到 AGH 工作区的 `extensions/` 下
2. 在**真实终端窗口**里执行（AGH 要求 TTY 确认，管道无效）：

```bash
agh install file:./extensions/agh-orbit-toolkit --profile local-dev   # 提示 [y/N] 时输入 y
agh package trust agh-orbit-toolkit <integrity> <capabilityHash>
agh package enable agh-orbit-toolkit
```

3. 确认：`agh package status` 显示 `desired=enabled actual=running trusted=true`
4. **重启控制台或开新会话**，插件在会话启动时加载

除核心闭环之外，还做了三项面向"可核性"的验证，各自的详细结果见 `docs/` 下对应文档：

| 验证 | 回答什么问题 | 关键结果 | 详细文档 |
| --- | --- | --- | --- |
| **统计置信区间** | "零误报零漏报"的依据有多强？ | 合格性判据 0/181、0/299，**95% 置信上界 1.64% / 1.00%**（Clopper-Pearson 精确法，与 scipy 对拍最大偏差 5.55e-16） | `agh-orbit-plugin/out/grid-eval.txt`（运行留档） |
| **外部权威基准对拍** | 实现和行业公认的实现一致吗？ | 与 **Orekit 官方测试**期望值对拍，位置/速度相对偏差 **1.2e-15**（双精度极限，逐位相同）；另对照 Curtis 教材例题 | `docs/外部基准对拍结果.html` |

## 一次真实的诊断过程

以下为实测记录（会话 `9b66886d`，单轮 8 个步骤，耗时 1 分 54 秒，**用户只给目标与一组待评估的配置、未指定任何步骤**）：

```
1. todo                   ← 自己拆出六项任务清单
2. orbit_kernel_info      比较五种方法，核验用户指定的 RK4 是否合适
3. orbit_calibrate_step   标定：最小 763 步/圈；浮点上界 6125 步/圈
4. orbit_propagate        763 步 → 位置误差 9.81e-6 km
5. orbit_order_test       实测阶 4.09 ≈ 理论阶 4，实现无问题
6. orbit_alarm_check      763 步触发 R5：弧段中段超差 2.6 倍
7. orbit_propagate        改用 6125 步 → 2.84e-9 km
8. orbit_alarm_check      6125 步的 R2 判定为浮点平台效应，非缺陷
→ 建议：用 6125 步/圈交付
```

**第 6 步是全过程最值得看的**：763 步末态误差恰好达标、算力最省，但它发现该配置**在弧段中段的误差会涨到 2.6 倍**——末态合格是假象。于是它**放弃了更省的方案，选了不会出事的那个**。

## 验证方法

**三条硬证据线：**

1. **代码间比对**——同一套物理用 Python 与 JavaScript **独立实现**，逐项比对（V&V 第 2 级）
2. **解析真值**——位置误差一律对开普勒解析解。这意味着"算得准不准"有**硬标准**，不依赖主观判断
3. **大样本统计**——六场景 480 单元的误报/漏报统计，**每条规则配一个独立于规则本身的真值**

**关键统计结果：**

| 规则 | 误报率 | 漏报率 |
| --- | --- | --- |
| **合格性判据（决定能否交付）** | **0.0%** | **0.0%** |
| 观测阶偏低 | 0.3% | 12.0% |
| 步长过小 | 1.7% | 11.1% |
| 弧段外推失效 | 0.0% | 24.4% |

## 与同期工作的关系

**本项目不提出新的数值验证理论。**

「用 LLM 智能体自动完成仿真验证」在 2026 年已有至少四项同期工作（Judge Agent、AutoCred、Möltner et al.、AIVV）。
我们做过完整的跨渠道新颖性核查（见 `docs/`），**不主张灵感独有**。

**本文的贡献是工程与流程层面的**：在一个具体领域内，把成熟的 V&V 方法做成完整、可复现、可审计的实现，
并让智能体承担编排与解释的角色。详细的差异界定与已知局限见
[`docs/与同期工作的关系说明.html`](docs/与同期工作的关系说明.html)。

**已知局限**（主动列出）：

- 不提出形式化理论
- 只覆盖二体问题与简谐振子，**不含 J2 及更高阶摄动**（解析真值是全部可信度主张的基准，这是刻意取舍）
- R5 规则用 2 倍弧段代理 4 倍真值，**漏报率 24.4%**（省一半算力的代价）
